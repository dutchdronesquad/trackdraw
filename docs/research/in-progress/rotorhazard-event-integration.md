# Native RotorHazard event integration contract

Status: implementation contract for [#887](https://github.com/dutchdronesquad/trackdraw/issues/887), prerequisite to [#888–#892](https://github.com/dutchdronesquad/trackdraw/issues/863). Assessed October 20, 2026. This defines the implementation; it does not claim a working plugin or host acceptance.

## Decision

Build `dutchdronesquad/rh-trackdraw` as a separate Python plugin, initially maintained by TrackDraw/Dutch Drone Squad, containing a locally bundled static viewer. This is the chosen repository name, to be created during #888; it is not an existing delivered repository. Keep it separate from the live timing/OBS integration `rh-stream-overlays`.

**RotorHazard changes are required.** The stable public Event page has no supported template insertion hook. Add native template slots, event-scoped storage/lifecycle and a reusable organizer authorization wrapper upstream before claiming compatibility. The plugin owns TrackDraw UI, validation, imports and rendering; RotorHazard owns native insertion and the event boundary. Do not replace `/event`, override RotorHazard templates, inject scripts through event descriptions/Markdown, rewrite responses or ship a detached viewer page.

Target inspected: latest tagged stable [RotorHazard v4.4.0](https://github.com/RotorHazard/RotorHazard/releases/tag/v4.4.0), commit `19e2e0aa82924754c337de9970bd439c684d69d8`, RHAPI **1.4**, Python minimum **3.10**. The baseline was exercised through source-level lifecycle probes; no hardware server, browser integration or offline LAN acceptance was run for this contract. Development-branch documentation is not the compatibility baseline. [RHAPI version](https://github.com/RotorHazard/RotorHazard/blob/19e2e0aa82924754c337de9970bd439c684d69d8/src/server/RHAPI.py#L1-L6), [release requirements](https://github.com/RotorHazard/RotorHazard/releases/tag/v4.4.0).

Pin both `@trackdraw/viewer` and `@trackdraw/schema` to **1.0.5**, without a range. Both versions were verified on npm; the matching source tag resolves to `a9517bec6cdf175210fb3d1d8f115de326de6f3e`. Source package manifests contain build-time `0.0.0` placeholders: consume published artifacts and retain their lockfile integrities. Recheck current stable RotorHazard and rerun the acceptance matrix at every plugin release. v4.4.0 alone is **not supported** until the RotorHazard dependency below is installed.

### Placement sketch

```text
/event — public, existing navigation       /format — organizer, existing Event panel
Event name                                Event
Event description                         Archive/New Event
                                          Event Name / Event Description
Track                                     Track: <title> · attached <time>
[2D] [3D] [fit] [fullscreen]               [Import .tdviewer.zip] [Choose TrackDraw project]
┌──────────────────────────────┐          <candidate preview + validation result>
│ local read-only track viewer │          [Attach / Replace track] [Cancel]
└──────────────────────────────┘          [Refresh from TrackDraw] [Remove track]
Heats                                     Cloud connection ▸ (optional, private settings)
Pilots / Classes / Formats                Remaining existing event controls
```

These are placement wireframes, not screenshots of an implemented UI. Use existing RotorHazard labels, panels and spacing; no nested panel/card. Stack controls on narrow screens. Preview does not activate a candidate. Replacement/removal requires an explicit action. Refresh is available for a cloud attachment; a local track can be replaced from either source. Visitors get read-only 2D/3D, with 2D fallback on unavailable WebGL; 3D starts on explicit use. The plugin loads its local scripts/styles through the native head slots and mounts into the native content slot.

## Event identity and lifecycle

RotorHazard's current database represents the current event; it is not a collection of event rows with a usable stable event ID. `eventName` is editable and archive filenames are not identities. In v4.4.0, `GlobalSettings` is a name/value table. `on_reset_database` clears race-related tables but retains plugin options even with `reset_type='all'`; `with_archive` changes event name/description after backup. `DATABASE_RESET` has no reset-type payload and occurs after UI emissions/confirmation. Event handlers default to asynchronous execution at priority 200; priority below 100 runs inline, but exceptions are logged and swallowed. A cleanup callback alone therefore cannot enforce the event boundary. [Settings model](https://github.com/RotorHazard/RotorHazard/blob/19e2e0aa82924754c337de9970bd439c684d69d8/src/server/Database.py#L437-L441), [reset/archive order](https://github.com/RotorHazard/RotorHazard/blob/19e2e0aa82924754c337de9970bd439c684d69d8/src/server/server.py#L1667-L1734), [handler execution](https://github.com/RotorHazard/RotorHazard/blob/19e2e0aa82924754c337de9970bd439c684d69d8/src/server/eventmanager.py#L90-L104).

| Action                                                              | Required attachment result                                                                                                                                                                                                            |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| First boot / legacy database                                        | Generate event UUID; no attachment. Do not discover a “last track” on disk.                                                                                                                                                           |
| Rename event, edit description, change heat or discard current laps | Keep UUID and attachment. Renaming is not starting an event.                                                                                                                                                                          |
| Archive/New Event                                                   | Archive old UUID plus complete attachment; rotate UUID and clear active attachment before exposing the new event.                                                                                                                     |
| Any explicit database reset, with or without archive                | Rotate UUID and clear attachment. Warn in organizer UI that reset removes the track from the current event; archived DB retains it. Conservative uniform behavior avoids relying on a missing reset payload.                          |
| Page reload / server restart                                        | Read current UUID and attachment from DB; revalidate stored data before serving. Never auto-fetch TrackDraw.                                                                                                                          |
| Backup/download `.db`                                               | Contains attachment bytes, public metadata and private source provenance; API key remains in server config and is not copied into the event DB. Treat backup as organizer-only.                                                       |
| Restore the archived event, same server or another installed server | Restore its UUID and complete local attachment; invalidate all process caches/candidates. Cloud refresh requires locally configured credentials; rendering never does.                                                                |
| Restore older DB without plugin data                                | New UUID, no track; never borrow attachment from the previously open DB.                                                                                                                                                              |
| Corrupt/incompatible restored attachment                            | Keep event/race data, display no track publicly and show an organizer diagnostic. No automatic network repair. Preserve invalid bytes for recovery.                                                                                   |
| Reset/restore during an import or cloud fetch                       | Reject activation with stale event/revision; discard candidate. Also fence with a process-local generation counter changed on every reset/restore, so restoring an identical UUID/revision cannot resurrect an old in-flight request. |

Existing backup copies the SQLite database, not arbitrary plugin files. Recovery explicitly selects tables and, on DB API upgrades, an allowlist plus registered UI options. A sidecar track folder or an unregistered option is therefore insufficient for portable restore; registering a large blob as a UI field is also inappropriate. The new RotorHazard table must be carried through recovery explicitly. [Backup implementation](https://github.com/RotorHazard/RotorHazard/blob/19e2e0aa82924754c337de9970bd439c684d69d8/src/server/RHData.py#L194-L260), [recovery selection](https://github.com/RotorHazard/RotorHazard/blob/19e2e0aa82924754c337de9970bd439c684d69d8/src/server/RHData.py#L391-L490), [UI option serialization](https://github.com/RotorHazard/RotorHazard/blob/19e2e0aa82924754c337de9970bd439c684d69d8/src/server/RHUI.py#L378-L400).

## Shared attachment and authorization contract

Use namespace `trackdraw.viewer.v1`, one active attachment per current event. Store the validated `.tdviewer.zip` bytes as the BLOB, not a remote URL. Metadata is a versioned plugin-owned envelope:

```json
{
  "version": 1,
  "title": "Race track",
  "snapshotId": "<validated snapshot content identity>",
  "archiveSha256": "<hash of complete archive bytes>",
  "attachedAt": "<UTC timestamp>",
  "viewerVersion": "1.0.5",
  "source": { "kind": "local", "filename": "race.tdviewer.zip" }
}
```

Cloud source instead records `{ "kind": "trackdraw", "projectId": "...", "fetchedAt": "..." }`. This is private organizer provenance, not public snapshot data. Local filenames are display-only and never filesystem paths. Event ID/revision live in the RotorHazard row, not user-provided metadata. API keys never enter snapshots, archives, browser HTML, event options, public responses or logs.

Both routes use `acquire → validate → stage → preview → explicit attach → atomic activation`. Each candidate captures event ID, active revision and current process generation; candidates are organizer-only and expire after 15 minutes or any lifecycle transition. Importing does not mutate the active attachment. Network failure, validation error, timeout, cancellation, stale candidate or concurrent replacement leaves the last valid attachment unchanged. Removal creates an empty active state and advances revision.

- **Local:** multipart upload of `.tdviewer.zip`; no account, key, API request or remote validation. Browser validation helps preview but the server independently validates before storage.
- **Cloud:** organizer configures a bearer key in private server config section `TRACKDRAW`; server requests `GET https://trackdraw.app/api/v1/projects` and `GET /api/v1/projects/{projectId}/viewer-snapshot`, using bearer permission `tracks: ["read"]` for both endpoints. Unwrap `response.data` and apply `viewerSnapshotFromApi`, then materialize all required assets into the same portable archive. Fetch only the fixed TrackDraw API origin and approved `https://assets.trackdraw.app/` asset paths; reject redirects/URLs outside the allowlist, credentials in URLs and local/private network destinations. Use a 3-second connection timeout, 15-second read timeout and 60-second overall import deadline; bound total bytes by the archive limits below. Never expose a general URL fetch endpoint. Refresh is explicit and stages a replacement; no startup, page-load or scheduled refresh.
- **Validation:** implement the pinned schema/archive semantics on the server, using Python fixtures shared with package tests; do not require Node on the race server or trust a browser “valid” flag. Validate schema `trackdraw.viewer-snapshot.v1`, design version 2, supported renderer capabilities, snapshot identity, complete exact asset manifest, SHA-256/size/content types, portable artwork permission and safe unique archive paths. Reject traversal, absolute paths, symlinks, duplicate members, extra executable files and ZIP bombs before activation. Limit archive and total expanded content to 64,000,000 bytes, snapshot to 4,000,000 bytes and each asset to 8,000,000 bytes. Reject incompatible data without replacing the track.

Published package sources: [API conversion](https://github.com/dutchdronesquad/track-viewer/blob/a9517bec6cdf175210fb3d1d8f115de326de6f3e/packages/schema/src/snapshot/api.ts), [archive rules and limits](https://github.com/dutchdronesquad/track-viewer/blob/a9517bec6cdf175210fb3d1d8f115de326de6f3e/packages/schema/src/snapshot/archive.ts), [renderer compatibility](https://github.com/dutchdronesquad/track-viewer/blob/a9517bec6cdf175210fb3d1d8f115de326de6f3e/packages/viewer/src/snapshot/archive.ts). Existing TrackDraw endpoints: [project list](../../../src/app/api/v1/projects/route.ts), [viewer snapshot](../../../src/app/api/v1/projects/[projectId]/viewer-snapshot/route.ts).

The following plugin-owned HTTP routes are part of the implementation contract, not existing endpoints:

| Route under `/trackdraw`                                                            | Access and behavior                                                                                                                                                               |
| ----------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /event`                                                                        | Public, no-store metadata: event ID, revision, title and local archive URL; 404 if no valid active track. Exclude source filename/project ID.                                     |
| `GET /event/<eventId>/<revision>/track.tdviewer.zip`                                | Public current attachment only, no-store; 404 on stale identity/revision. No arbitrary DB/archive lookup. Local viewer loads this complete archive.                               |
| `GET /static/<release>/<path>`                                                      | Public installed JS/CSS/assets, versioned immutable files; restrict paths to the installed bundle. No CDN, remote fonts or analytics.                                             |
| `POST /manage/import`, `POST /manage/projects/<projectId>/preview`                  | Organizer authorization plus same-origin/CSRF protection; produce an expiring candidate.                                                                                          |
| `POST /manage/activate`, `POST /manage/refresh`, `POST /manage/remove`              | Organizer authorization plus same-origin/CSRF protection; require expected event ID/revision and candidate/generation checks. Refresh stages a candidate for explicit activation. |
| `GET /manage/state`, `GET /manage/projects`, `GET /manage/candidates/<candidateId>` | Organizer-only metadata, project list and preview; no-store. Candidate IDs are opaque, never public attachment identifiers.                                                       |
| `POST /manage/connection`                                                           | Organizer-only, same-origin/CSRF protected; write private key server-side. Return only configured status, never the key.                                                          |

Apply RotorHazard's organizer policy on every request: valid HTTP Basic credentials when configured; the existing intentionally open-admin mode when both admin fields are empty or first-run config is absent. Do not pretend that mode supplies individual organizer accounts. Do not infer authorization from a prior page load or a Socket.IO connection. Require exact-origin validation and an authenticated, server-issued CSRF token on mutations; no state-changing GETs or permissive CORS. Public visitors cannot activate, remove, refresh or enumerate cloud projects. [Stable auth semantics](https://github.com/RotorHazard/RotorHazard/blob/19e2e0aa82924754c337de9970bd439c684d69d8/src/server/server.py#L379-L423).

Public content is deliberately readable by anyone who can reach the race server, matching `/event`; attaching a private TrackDraw project deliberately publishes its snapshot to that audience. Explain this beside Attach. Public rendering uses the local archive only, without TrackDraw credentials, runtime API requests or tracking. No live timing, pilot markers, OAuth or bidirectional editing.

## Repository and release layout

```text
rh-trackdraw/
  plugins/rh_trackdraw/
    __init__.py, manifest.json       # capability gate, blueprint and native fragments
    attachments.py, validation.py   # shared pipeline and RotorHazard event storage adapter
    cloud.py, routes.py             # organizer-only TrackDraw calls and local reads
    templates/rh_trackdraw/         # event and organizer fragments
    static/<plugin-version>/       # pinned viewer global JS/CSS + local UI assets
  tests/fixtures/                   # accepted/rejected archives shared with viewer semantics
  build/package-lock.json          # exact viewer/schema pins and npm integrity
  release/                         # generated install ZIP, checksums, SBOM, licenses/notices
  docs/acceptance.md                # RotorHazard commit/API, plugin/viewer versions and matrix
```

Build-time Node is allowed; runtime Python only. Package `dist/static/trackdraw-viewer.global.js` and `trackdraw-viewer.css` plus every required local static dependency from the pinned npm release. Use `TrackDrawViewer.mountTrack(container, { source: localArchiveUrl })` and destroy the handle when replacing/unmounting. Keep track-specific artwork inside the attachment, not a global catalog download. Include Apache-2.0 notices and applicable artwork attribution. The release ZIP installs `rh_trackdraw/` into the current RotorHazard data directory's `plugins/` folder (the data directory is normally `~/rh-data`); include all Python dependencies not supplied by the supported server, so installation never invokes pip/npm or requires WAN. Record exact RotorHazard dependency and checksums in release metadata. [Static exports](https://github.com/dutchdronesquad/track-viewer/blob/a9517bec6cdf175210fb3d1d8f115de326de6f3e/packages/viewer/src/static.ts), [plugin installation layout](https://github.com/RotorHazard/RotorHazard/blob/19e2e0aa82924754c337de9970bd439c684d69d8/doc/Plugins.md).
