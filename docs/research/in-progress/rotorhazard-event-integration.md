# Native RotorHazard event integration contract

Status: implementation contract for [#887](https://github.com/dutchdronesquad/trackdraw/issues/887), prerequisite to [#888–#892](https://github.com/dutchdronesquad/trackdraw/issues/863). Assessed October 20, 2026. Plugin implementation and offline host acceptance remain open.

## Decision and supported versions

Build a separate Python plugin in `dutchdronesquad/rh-trackdraw`, initially maintained by TrackDraw/Dutch Drone Squad. This is the chosen repository name, to be created during #888. The plugin bundles the static viewer and supports one active track per event. Local file import and TrackDraw project selection use the same validation and storage. No live timing, pilot markers, OAuth or bidirectional editing.

**RotorHazard changes are required** for native placement and reliable event lifecycle handling. The plugin owns imports, validation, track display and attachment controls. RotorHazard supplies the two native insertion points and clears/restores the event attachment with its event data. There is no detached viewer page or TrackDraw-hosted iframe.

Inspected baseline: latest tagged stable [RotorHazard v4.4.0](https://github.com/RotorHazard/RotorHazard/releases/tag/v4.4.0), commit `19e2e0aa82924754c337de9970bd439c684d69d8`, RHAPI **1.4**, Python minimum **3.10**. Pin published `@trackdraw/viewer` and `@trackdraw/schema` to **1.0.5**, without a range; matching source commit `a9517bec6cdf175210fb3d1d8f115de326de6f3e`. Both package versions were verified on npm. Recheck the latest stable RotorHazard release before each plugin release. Unmodified v4.4.0 does not yet support this integration. [RHAPI version](https://github.com/RotorHazard/RotorHazard/blob/19e2e0aa82924754c337de9970bd439c684d69d8/src/server/RHAPI.py#L1-L6).

## Event storage and lifecycle

The current RotorHazard database represents the current event. `eventName` is editable and cannot identify it. Store an opaque event ID separately from the attachment. The attachment holds that event ID, the complete validated archive, title, snapshot identity, attachment time and source information. Local source information is a display filename; cloud source information is the project ID and fetch time. Never store an API key in event data.

Reuse private database options, storing the archive in a bounded serialized record. Both imports write the same record. Event ID and attachment updates must remain consistent across reset and restore. Replacement is atomic: validation and asset collection complete before saving. Recheck the active event at save time and prevent overlapping changes from silently overwriting each other. Reset/restore cancels any import or preview already in progress, including when restoring the same event. This requires a checked save operation coordinated with lifecycle changes, not a cleanup callback after the fact; its implementation belongs in #888.

| Action                                                                 | Attachment result                                                                                                                                                                              |
| ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| First boot or legacy database without event data                       | New event ID; no track. Never pick a previous track from disk.                                                                                                                                 |
| Rename, description edit, heat change or discard current laps          | Keep event ID and track.                                                                                                                                                                       |
| Archive/New Event                                                      | Archive the old event with its full track first; then start a new event with no attachment.                                                                                                    |
| Any explicit database reset, with or without archive                   | New event ID and no track. In v1 this applies to all six reset modes, including races-only and formats-only; explain this beside reset controls. Ordinary lap discard is not a database reset. |
| Reload or server restart                                               | Keep the event and validated local track; no automatic TrackDraw fetch.                                                                                                                        |
| Backup/download `.db`                                                  | Includes complete attachment and source information. Credentials remain in server config.                                                                                                      |
| Restore on the same server or another server with the plugin installed | Restore that event's ID and full track; discard pending work and cached selections. Rendering needs no cloud credentials.                                                                      |
| Restore legacy data without an attachment                              | No track; never reuse the previously open event's attachment.                                                                                                                                  |
| Invalid/incompatible attachment or failed recovery                     | Show no track publicly and an organizer diagnostic; preserve recoverable data. No fallback to another event's track.                                                                           |
| Failed/interrupted import or refresh                                   | Keep the previous valid track while the same event remains active. An event change prevents the pending replacement from saving.                                                               |

Why explicit RotorHazard changes are necessary: `on_reset_database` retains plugin options even for `reset_type='all'`. `DATABASE_RESET` arrives without reset details, after UI updates, and default event handlers run asynchronously. Backups copy SQLite only; recovery rebuilds known data and uses an option allowlist during database API migration. A plugin option without lifecycle/recovery support is therefore insufficient. [Reset/archive handling](https://github.com/RotorHazard/RotorHazard/blob/19e2e0aa82924754c337de9970bd439c684d69d8/src/server/server.py#L1667-L1734), [event dispatch](https://github.com/RotorHazard/RotorHazard/blob/19e2e0aa82924754c337de9970bd439c684d69d8/src/server/eventmanager.py#L90-L104), [backup](https://github.com/RotorHazard/RotorHazard/blob/19e2e0aa82924754c337de9970bd439c684d69d8/src/server/RHData.py#L194-L260), [recovery](https://github.com/RotorHazard/RotorHazard/blob/19e2e0aa82924754c337de9970bd439c684d69d8/src/server/RHData.py#L391-L490).

## Import and access contract

Both routes use **load → validate → preview → explicit save**, with one shared server-side validator and local attachment store. Browser preview does not authorize or replace server validation. No separate preview service, candidate token system or expiry policy is required.

- **Local:** import `.tdviewer.zip` without a TrackDraw account, key or network call.
- **TrackDraw:** keep the bearer key in private server config. The server uses `GET https://trackdraw.app/api/v1/projects` and `GET /api/v1/projects/{projectId}/viewer-snapshot`, with permission `tracks: ["read"]`. Convert `response.data` using the published `viewerSnapshotFromApi` contract and collect all required assets into the same complete local archive. Fetch only the fixed API origin and approved `https://assets.trackdraw.app/` paths, with bounded timeouts and download sizes. Reject redirects outside those origins and private/local network destinations. Refresh is explicit; never fetch on visitor page load or server startup.
- **Validation:** follow schema `trackdraw.viewer-snapshot.v1`, design version 2 and the pinned viewer's compatibility/archive rules. Verify snapshot identity, complete asset manifest, hashes, sizes, content types, portable artwork permissions and safe unique paths. Reject extra executable files, traversal and ZIP bombs. Maximum archive/expanded content: 64,000,000 bytes; snapshot: 4,000,000 bytes; each asset: 8,000,000 bytes. Incompatible or incomplete data cannot replace the active track.

Published package sources: [API conversion](https://github.com/dutchdronesquad/track-viewer/blob/a9517bec6cdf175210fb3d1d8f115de326de6f3e/packages/schema/src/snapshot/api.ts), [archive rules](https://github.com/dutchdronesquad/track-viewer/blob/a9517bec6cdf175210fb3d1d8f115de326de6f3e/packages/schema/src/snapshot/archive.ts), [renderer compatibility](https://github.com/dutchdronesquad/track-viewer/blob/a9517bec6cdf175210fb3d1d8f115de326de6f3e/packages/viewer/src/snapshot/archive.ts). Existing TrackDraw endpoints: [project list](../../../src/app/api/v1/projects/route.ts), [viewer snapshot](../../../src/app/api/v1/projects/[projectId]/viewer-snapshot/route.ts).

All import, preview, project-selection, connection, refresh and removal requests use RotorHazard's organizer authorization. Respect configured HTTP Basic credentials and its existing intentionally open-admin mode. Protect mutations against cross-origin requests and CSRF; do not use state-changing GETs. Keep credentials out of browser responses, snapshots, backups and logs. [Existing authorization policy](https://github.com/RotorHazard/RotorHazard/blob/19e2e0aa82924754c337de9970bd439c684d69d8/src/server/server.py#L379-L423).

Public reading matches `/event`: anyone who can reach the race server can view the attached track. Explain beside Attach that choosing a private TrackDraw project makes its snapshot public to that audience. Serve only the current event's track and required local assets; no private source metadata, credentials, remote runtime requests or tracking.

## Offline release and handoff

Ship a versioned plugin ZIP containing the pinned static viewer JS/CSS, required dependencies, licenses/notices and installation instructions. Install the plugin folder into the current RotorHazard data directory's `plugins/` folder. No runtime Node, npm, pip or WAN access is required. Track-specific artwork travels inside its attachment. Record plugin, viewer and required RotorHazard versions/commits in the release.
