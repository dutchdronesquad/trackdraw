# TrackDraw efficiency on Cloudflare Free

Research date: October 20, 2026. The account owner confirmed Workers Free. This note records platform constraints and source inspection; it does not claim that every limit is currently being approached. Production traffic, development acceptance traffic and local timing must be reported separately.

## The limits that matter

| Resource              | Included allowance                                                                                              | Practical implication                                                                                                                                                                                                                                 |
| --------------------- | --------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Worker execution      | 100,000 requests/day; 10 ms CPU per HTTP request and per Cron invocation; 128 MB memory; 50 subrequests/request | Avoid entering the Worker for static files, and bound work inside dynamic requests. Network/database waiting does not consume CPU; parsing, serialization, auth and geometry do. The isolate's occasional CPU flexibility is not a dependable budget. |
| Workers Static Assets | Free, unlimited asset requests and no additional asset-storage charge                                           | An asset hit that bypasses Worker execution does not consume the same request budget. `run_worker_first` changes that boundary.                                                                                                                       |
| D1                    | 5 million rows read/day; 100,000 rows written/day; 5 GB total storage                                           | Count rows scanned rather than returned rows or number of SQL calls. Indexes reduce scans but add write/storage costs. Reaching daily read/write limits stops queries until reset.                                                                    |
| R2 Standard           | 10 GB-month storage; 1 million Class A and 10 million Class B operations/month; free egress                     | `PUT`/`LIST` and `GET`/`HEAD` remain metered operations even though bandwidth is free. These allowances do not cover Infrequent Access.                                                                                                               |
| Workers Logs          | 200,000 events/day; three-day retention                                                                         | Invocation logs plus application logs can produce multiple events per request. Keep enough evidence to diagnose failures; measure volume before selecting a sampling rate. Pricing changes December 1, 2026.                                          |

Sources: [Workers limits](https://developers.cloudflare.com/workers/platform/limits/), [Static Assets billing](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/), [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/), [R2 pricing](https://developers.cloudflare.com/r2/pricing/), [Workers Logs pricing](https://developers.cloudflare.com/workers/observability/logs/workers-logs/#pricing). These quotas describe different resources and reset periods; gzip bytes are not a substitute for measuring runtime CPU or daily requests.

## Existing protections worth retaining

- [Wrangler config](../../../wrangler.jsonc) sets `assets.run_worker_first: false`. Matching public files and build chunks can bypass the Worker. Production minifies the upload; development currently disables minification. Handler-size budgets in [the build guard](../../../scripts/check_worker_size.mjs) are TrackDraw's own regression limits, separate from runtime CPU.
- [OpenNext config](../../../open-next.config.ts) enables cache interception only for the four prerendered public shells: `/`, `/studio`, `/privacy` and `/terms`. [The deployment guide](../../deployment/deployment-setup.md#static-public-shell) correctly distinguishes avoiding `NextServer` work from avoiding Worker invocation. [OpenNext's supported read-only Static Assets cache](https://opennext.js.org/cloudflare/caching#ssg-site) suits these build-time pages; it does not support revalidation. Expanding it to account/share/gallery results would need a different correctness contract.
- [Public headers](../../../public/_headers) give fingerprinted Next.js chunks a one-year immutable cache. This follows [OpenNext's documented static-asset setup](https://opennext.js.org/cloudflare/caching#static-assets-caching). Unversioned locale/artwork files must retain a refresh path.
- [Share-page data](../../../src/lib/server/share-page-data.ts) already uses request-local React memoization so metadata and rendering share reads without persisting a stale authorization/revocation decision. [Account activity](../../../src/lib/server/account-activity.ts) skips recent activity updates and conditionally writes at most daily under concurrency.
- [Cloud-project sync](../../../src/components/editor/useAccountProjectSync.ts) coalesces focus/visibility refresh work. [Editor autosave and periodic restore points](../../../src/hooks/editor/useEditorProjects.ts) are local persistence, so their timer frequency is not itself a Cloudflare cost. High-cardinality gallery/editor links already opt out of prefetching in several surfaces.

## Measured baseline and first correction

Read-only measurements on October 20, 2026:

| Measurement                                                        | Production                                        | Development                           |
| ------------------------------------------------------------------ | ------------------------------------------------- | ------------------------------------- |
| Worker invocations, October 19 15:09:10 to October 20 15:09:10 UTC | 911 successful, 6 client disconnects              | 706 successful, 7 `exceededResources` |
| D1 table introspection, previous 1 day                             | 1,820 `pragma_table_info` calls, 15,708 rows read | 12,971 calls, 133,829 rows read       |
| D1 schema-table listing, previous 1 day                            | 86 calls, 9,288 rows read                         | 403 calls, 62,062 rows read           |

Worker figures come from the [GraphQL Workers metrics dataset](https://developers.cloudflare.com/analytics/graphql-api/tutorials/querying-workers-metrics/), grouped by script and outcome; static-asset hits that bypass the Worker are outside these counts. The dataset does not identify route families in this query. `exceededResources` alone does not identify which resource was exhausted; the earlier MCP tail separately established CPU exhaustion. Counts are a snapshot, not a traffic forecast, and development includes acceptance-test traffic. A follow-up GraphQL type-introspection query was API-rate-limited, so avoid repeatedly collecting broad analytics queries.

The largest production SQL shape in the returned top-15 reads sample was the dashboard session-journey aggregate in [metrics.ts](../../../src/lib/server/metrics.ts): 246,540 rows read across 12 calls (20,545 per call). A read-only production `EXPLAIN QUERY PLAN` confirmed indexed event-date filtering and indexed creator-activation lookup. This is a priority for reducing repeated/expensive dashboard work, not evidence that another index is missing. The top-15 query sample is not the account's complete daily D1 usage.

The first implemented correction moves repeated auth schema introspection to CI and the predeployment schema gate described below. A regression using the full auth factory reproduced 62 metadata queries for two fresh auth requests before the change and zero afterward. The separate full-config check accepts all migrations and the real development schema, and its negative regression rejects a missing auth column. Live session reads and revocation remain covered. This establishes removed SQL work, not a percentage reduction in deployed CPU or a guarantee that every request fits Workers Free; compare deployed Insights/CPU after release.

The sibling [viewer demo configuration](https://github.com/dutchdronesquad/track-viewer/blob/main/wrangler.demo.jsonc) is assets-only, with no application Worker handler. Its fingerprinted chunks are immutable and entry points revalidate. There is no source-level reason to add a Worker/cache layer to that host for this investigation.

## Authentication schema-check overhead

[Better Auth's documented schema validation](https://better-auth.com/docs/concepts/database#schema-validation) is enabled in production by default, reads live Kysely metadata during initialization, and caches its result per adapter instance. [TrackDraw's auth factory](../../../src/lib/server/auth.ts) creates an instance for each call, so repeated metadata queries are a concrete investigation target. The supported `advanced.database.validateSchema: false` option now removes runtime introspection. The actual factory supports an explicit validation mode; CI checks all repository migrations, and both deployment workflows run the same full-config check against a local copy of the selected target database schema after migrations. [The check script](../../../scripts/check_auth_schema.mjs) reads table/index definitions only, performs no remote writes, and removes its temporary files. The deploy job depends on this gate passing. Keep actual token/session/consent/ownership checks live. This is different from caching authentication decisions or reusing request-bound database state across requests.

## Decisions to keep simple

Avoid persistent caches for session, ownership, consent, revocation or quota decisions. Do not replace request work with a growing set of KV/R2/DO lookups without measuring its added requests, writes and consistency burden. A shorter bundle may improve startup and deployment size but does not prove that a particular authenticated/geometry request fits 10 ms. First remove redundant work and unnecessary calls while preserving the existing product contracts; any remaining architectural change needs a measured bottleneck and its own validation.
